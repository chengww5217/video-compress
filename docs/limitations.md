# 已知限制

- **交错片源**（DVD / 电视台 rip，`field_order` 是 `tt/bb/tb/bt`）会被**跳过**，不做处理。压过去的话像素本身不变，但容器的交错标记会丢——AV1 根本没有交错信号——播放器从此不再反交错，梳齿就留在画面上了。这和色彩元数据丢失是同一类问题：VMAF 逐帧比对测不出来，但确实是视觉有损，所以不能压，更不能压完删掉原文件。反交错属于"动画面"，不在本工具范围内，唯一正确的处置就是不碰；真要照压设 `[skip] skip_interlaced = false`。telecine（3:2 pulldown）检测不出来（元数据里没有这个信息，得逐帧分析），这类片源仍需自己排除。
- **VFR 片源**：VMAF 抽样按平均帧率对齐切点，异常片源可能触发假警报；已有前后各挪一帧的复核兜底，实在对不齐会记为校验失败并保留原文件（不会误删）。
- **mp4 风格的封面图**（作为 `attached_pic` 视频流存在的那种）会被丢弃：编码时用 `-map 0:V` 排除了它，否则封面会被当成视频轨去编码。mkv 的附件（含封面、字体）照常保留。
- 边界一节列的那些事都不做——需要裁黑边、降分辨率、颗粒合成的话，用 av1an / StaxRip 之类的工具更合适。

# 常见问题

**Q：为什么压缩很慢？**
默认 preset 2/placebo 是极限压缩档，一部电影可能需要数小时。这是设计取向（时间换体积）。想加速可调低 `[encode.av1].preset`（如 6~8），体积会稍大。

**Q：想更激进地缩小体积？**
把 `[adaptive].target_vmaf` 从 95 降到 92~93——这是唯一真正的旋钮，因为体积由画质闸门决定。编码器节里的 `crf` 只在 `--no-adaptive` 时才起作用，自适应开着时它会被搜索结果覆盖。

**Q：某些播放设备放不了 AV1？**
改用 `python -m vcompress ... --encoder x265`，或在配置里永久切换。

**Q：如何强制重新压缩已处理过的文件？**
`--force` 只忽略 `results.jsonl` 缓存，元数据标记依然生效。要连标记一起绕过，把 `[skip].tag_marker` 改成另一个值（检测跟着配置走），必要时再清空 `expected_ratio`/`bpp` 两张表。

**Q：启动就报 `unknown option [skip] xxx` 怎么办？**
配置里有代码不认识的键，通常是拼写错误。报错信息里的键名就是问题所在；确认拼写或删掉该行即可。
